## PART A — CHEAT SHEET

### A1. Where GA sits

- Local search = keep **one current state** (or k states), move to neighbours, **don't keep the path**.
- Use it when **only the final state matters**, not how you got there (8-queens, VLSI layout, job-shop scheduling, vehicle routing, portfolio management).
- Two advantages: **constant memory**, and works in **huge or continuous** state spaces.
- Landscape terms: *location* = state, *elevation* = objective/cost value. Objective function → find **global maximum**; cost function → find **global minimum**.
- The family: hill climbing → simulated annealing → local beam search → **genetic algorithms**.

> **Exam one-liner:** *"A genetic algorithm is a variant of **stochastic beam search** in which successor states are generated by combining **two parent states** rather than by modifying a single state."*

### A2. Biological vocabulary

| Term | Meaning in GA |
|---|---|
| Chromosome / individual / string | One candidate solution |
| Gene | One position in the string |
| Allele | The value a gene can take |
| Population | The set of chromosomes in the current generation |
| Fitness | Numeric quality of a chromosome |
| Offspring | Child produced by crossover/mutation |
| Generation | One full cycle of the loop |

### A3. The basic GA — memorise this loop

```
1. [START]      Generate a random population of n chromosomes
2. [FITNESS]    Evaluate f(x) for every chromosome
3. [NEW POP]    Repeat until the new population is full:
     a. [SELECTION]  Pick 2 parents, biased by fitness
     b. [CROSSOVER]  With probability Pc, recombine to make offspring
                     (else offspring = exact copies of parents)
     c. [MUTATION]   With probability Pm, flip/alter genes in offspring
     d. [ACCEPTING]  Place offspring into the new population
4. [REPLACE]    New population becomes the current population
5. [TEST]       If termination condition met -> return best solution
6. [LOOP]       Otherwise go to step 2
```

Termination conditions: solution found / max generations reached / fitness stops improving / time budget exhausted.

### A4. Encoding (know all four, with an example each)

| Encoding | Chromosome looks like | Typical problem |
|---|---|---|
| **Binary** | `10110010` | Knapsack, maximise f(x) over an integer range |
| **Value / real** | `1.23 5.32 0.45` or `ABDJEIFJ` | Neural network weights |
| **Permutation** | `1 5 3 2 6 4 7 9 8` | Travelling Salesman, task ordering |
| **Tree** | expression tree `(+ x (/ 5 y))` | Genetic programming, evolving formulas |

Binary encoding is the most common: short strings, many possible chromosomes, but often **unnatural** for the problem and needs a decoding step.

### A5. Operator 1 — SELECTION (the topic you flagged)

Purpose: choose parents so that **fitter chromosomes reproduce more often**, without killing diversity.

**Roulette wheel selection** — the method examined in this course:

1. Compute fitness `f_i` for every chromosome.
2. Compute total fitness `F = Σ f_i`.
3. Compute selection probability `p_i = f_i / F`.
4. Build **cumulative bins** — chromosome 1 gets `[0, p_1]`, chromosome 2 gets `(p_1, p_1+p_2]`, and so on up to 1.00.
5. Generate a random number `r` in `[0, 1]`.
6. The bin that contains `r` names the selected parent.
7. Repeat until you have as many parents as you need.

Wheel intuition: each chromosome owns a slice of the wheel proportional to its fitness. Spin once per parent.

**Note on negative fitness:** if `f(x)` comes out negative, this course **clamps it to 0** — that chromosome gets probability 0 and no bin, so it can never be selected. (See string 5 in the worked example.)

**Other selection schemes worth naming if asked to compare:**

| Scheme | How it works | Why use it |
|---|---|---|
| Roulette wheel | Slice ∝ fitness | Simple, standard |
| Rank selection | Sort, then slice ∝ **rank**, not raw fitness | Stops one huge-fitness chromosome dominating; helps when all fitnesses are close |
| Tournament | Pick k at random, best one wins | Cheap, tunable pressure |
| Elitism | Copy the best 1–2 chromosomes **unchanged** into the next generation | Guarantees the best solution is never lost by crossover/mutation |
| Steady-state | Replace only a few worst chromosomes each generation | Slow, stable convergence |

### A6. Operator 2 — CROSSOVER

| Type | Rule |
|---|---|
| **One-point** | Choose one cut point; child = parent1's head + parent2's tail |
| **Two-point** | Choose two cut points; swap the middle segment |
| **Uniform** | For each gene independently, randomly take it from P1 or P2 (often via a random mask) |
| **Arithmetic** | Apply an arithmetic operation to the parents, e.g. child = AND / OR of the parents, or a weighted average for real values |
| **Heuristic** | Use the **fitness values** of the parents to bias the child: `child = best + r × (best − worst)`; produces a child near the fitter parent |
| **Three-parent** | Compare P1 and P2 gene by gene: if `P1 == P2` take that bit, else take the bit from P3. Rotate the roles (P1,P3,P2) and (P2,P3,P1) to make offspring 2 and 3 |

One-point example:
```
P1 = 1 1 0 1 1 | 0 0 1
P2 = 0 1 0 0 1 | 1 1 0
------------------------
O1 = 1 1 0 1 1 | 1 1 0
O2 = 0 1 0 0 1 | 0 0 1
```

### A7. Operator 3 — MUTATION

- Keeps **diversity**, prevents the population getting stuck in a local optimum.
- Applied with a **low probability** (typically ~1%).
- **Flip-bit mutation** (binary): pick a gene, flip `0↔1`.
  `1 0 1 1 0` → mutate gene 2 → `1 1 1 1 0`
- **Order-changing mutation** (permutation): swap two positions, so the string stays a valid permutation.
- Too much mutation = the search degenerates into a random walk. Too little = premature convergence.

### A8. Crossover vs mutation — the classic compare question

| | Crossover | Mutation |
|---|---|---|
| Parents | Two | One |
| Role | **Exploitation** — combines good building blocks that already exist | **Exploration** — introduces genes not present in the population |
| Probability | High (`Pc` ≈ 0.6–0.9) | Low (`Pm` ≈ 0.01) |
| Effect if removed | Population stops mixing, GA degrades toward parallel hill climbing | Loses diversity, converges prematurely to a local optimum |

## PART B — WORKED EXAMPLES (learn these; the quiz reuses the format)

### B1. 8-Queens as a GA problem

**Representation.** A chromosome is 8 digits. **Digit position = column, digit value = the row of the queen in that column.** So `24748552` means: column 1's queen is in row 2, column 2's in row 4, column 3's in row 7, and so on. This automatically enforces one queen per column.

**Fitness function.** `fitness = number of NON-attacking pairs of queens`.

```
max pairs for 8 queens  = C(8,2) = 8×7/2 = 28
max pairs for n queens  = C(n,2) = n(n-1)/2 = n! / (2!(n-2)!)
minimum = 0,  a perfect solution scores 28
```

**How to count attacks fast.** Two queens attack if they share a **row** or a **diagonal** (they can never share a column here). For a diagonal: `|column difference| == |row difference|`. Walk left to right; for each queen count attacks only against queens to its **right**, so no pair is double-counted.

**Worked count for `24748552`:**

Columns and rows: (1,2) (2,4) (3,7) (4,4) (5,8) (6,5) (7,5) (8,2)

| Attack | Reason |
|---|---|
| col1 & col8 | same row 2 |
| col2 & col4 | same row 4 |
| col6 & col7 | same row 5 |
| col3 & col8 | diagonal: Δcol = 5, Δrow = 7−2 = 5 |

Per-column tally as shown in the slides: `1, 1, 1, 0, 0, 1, 0, 0` → **4 attacking pairs**

```
fitness = 28 − 4 = 24 non-attacking pairs
```

**Selection probabilities for the four-state population.** The four states score `24, 23, 20, 11`; total = 78.

| State | Fitness | p = f/78 |
|---|---|---|
| 24748552 | 24 | 24/78 = **31%** |
| 32752411 | 23 | 23/78 = **29%** |
| 24415124 | 20 | 20/78 = **26%** |
| 32543213 | 11 | 11/78 = **14%** |

**Crossover for 8-queens.** Pick a crossover point, swap the tails:
```
P1 = 327 | 52411        O1 = 327 | 48552
P2 = 247 | 48552        O2 = 247 | 52411
```

**Mutation for 8-queens.** Change one digit — i.e. **move one queen up or down within its own column**. `24748552` → `24748**1**52`.

### B2. Lecture exercise — attacks on `76012345` and `66743210`

Column indices from 0; digit = row.

**`76012345`** → (0,7)(1,6)(2,0)(3,1)(4,2)(5,3)(6,4)(7,5)
- Same row: none (all eight rows are different).
- Diagonals: `(0,7)-(1,6)` plus the long descending run `(2,0)(3,1)(4,2)(5,3)(6,4)(7,5)` — six queens on one diagonal contribute C(6,2) = 15 pairs.
- **Attacks = 1 + 15 = 16 → fitness = 28 − 16 = 12**

**`66743210`** → (0,6)(1,6)(2,7)(3,4)(4,3)(5,2)(6,1)(7,0)
- Same row: `(0,6)` and `(1,6)` → 1 pair.
- Diagonals: `(1,6)` descends through `(2,7)`? no — `(1,6)-(2,7)` is Δ1/Δ1, yes; `(1,6)` also lines up with `(3,4)(4,3)(5,2)(6,1)(7,0)`. Plus the run `(3,4)(4,3)(5,2)(6,1)(7,0)` is itself one diagonal → C(5,2) = 10 pairs. Total diagonal pairs = 16.
- **Attacks = 1 + 16 = 17 → fitness = 28 − 17 = 11**

So `76012345` is the fitter of the two.

### B3. Lecture exercise — 6-Queens fitness

Chromosomes `211345`, `403234`, `511023`; column indices from 0. Max pairs = 6×5/2 = **15**.

| Chromosome | Same-row pairs | Diagonal pairs | Attacks | **Fitness (non-attacking)** |
|---|---|---|---|---|
| 211345 | 1 | 7 | 8 | **7** |
| 403234 | 2 | 7 | 9 | **6** |
| 511023 | 1 | 2 | 3 | **12** |

`511023` is the best of the three.

*Check for 511023* → (0,5)(1,1)(2,1)(3,0)(4,2)(5,3): same row 1&2 → 1 pair; diagonals `(2,1)-(3,0)` and `(4,2)-(5,3)` → 2 pairs. Total 3. `15 − 3 = 12`.

### B4. The full GA numerical example — MEMORISE THIS ONE

**Problem.** Maximise `f(x) = x²/2 − 3x` for `x ∈ [0, 31]`. Binary encoding, 5 bits (since 2⁵ = 32 covers 0–31). Population size 6.

**Step 1 — Initialisation + fitness + SELECTION setup**

| String | Chromosome | x | f(x) = x²/2 − 3x | Probability | Bin |
|---|---|---|---|---|---|
| 1 | `10010` | 18 | 108 | 0.211 | 0.001 – 0.211 |
| 2 | `10011` | 19 | 123.5 | 0.242 | 0.212 – 0.453 |
| 3 | `10111` | 23 | 195.5 | 0.383 | 0.454 – 0.836 |
| 4 | `01110` | 14 | 56 | 0.110 | 0.837 – 0.946 |
| 5 | `00101` | 5 | **0** (raw −2.5, negative → 0) | 0 | — |
| 6 | `01011` | 11 | 27.5 | 0.054 | 0.947 – 1.00 |
| **Total** | | | **510.5** | **1.00** | |

*Sample check:* x = 23 → `23²/2 − 3(23) = 264.5 − 69 = 195.5`; p = `195.5 / 510.5 = 0.383`.

**Step 2 — Spin the wheel four times (select 4 parents)**

| Random number | Bin hit | Chosen parent | After crossover | After mutation (1%) |
|---|---|---|---|---|
| 0.54 | 3 | `10111` | `10110` | `1**1**110` |
| 0.88 | 4 | `01110` | `01111` | `01111` |
| 0.45 | 2 | `10011` | `10010` | `10010` |
| 0.20 | 1 | `10010` | `10011` | `10011` |

Crossover here is one-point, cutting before the **last bit**, applied to pair (1,2) and pair (3,4). Mutation flipped gene 2 of the first offspring only.

**Step 3 — Accept / Survival**

| Offspring | x | f(x) |
|---|---|---|
| `11110` | 30 | **360** |
| `01111` | 15 | 67.5 |
| `10010` | 18 | 108 |
| `10011` | 19 | 123.5 |

**Step 4 — Updated population** — the strong offspring `11110` (fitness 360, far above the previous best of 195.5) enters the population as string 7:

`10010, 10011, 10111, 01110, 00101, 01011, 11110`

**Step 5 — Check the termination condition.** Not met → start a new cycle from Step 1.

## PART D — ANSWERS

1. **stochastic beam** search; **combining two parent states** rather than modifying a single state.
2. Start (random population) → Fitness (evaluate) → New population (selection, crossover, mutation, accepting) → Replace → Test (termination) → Loop.
3. Binary (knapsack / maximise f(x)); Value or real (neural-network weights); Permutation (travelling salesman, task ordering); Tree (genetic programming, evolving expressions).
4. Fitness = number of **non-attacking pairs** of queens. Max = C(8,2) = 28. For n queens: `n(n−1)/2 = n! / (2!(n−2)!)`.
5. High mutation destroys the good building blocks that crossover has assembled and turns the search into a random walk. A low rate injects just enough new genetic material to escape local optima.
6. Crossover uses two parents / mutation uses one. Crossover exploits existing genes, mutation explores genes not in the population. Crossover probability is high (~0.6–0.9), mutation low (~0.01).
7. Elitism copies the best one or two chromosomes **unchanged** into the next generation. It prevents the best solution found so far from being destroyed by crossover or mutation.
8. It is clamped to **0**. With fitness 0 its probability is 0 and it receives **no bin on the wheel**, so it can never be selected as a parent.

### Traps to avoid

- Fitness for 8-queens is **non-attacking** pairs, not attacking. Higher is better. Do not report 4 when the answer is 24.
- Count each attacking pair **once**. Walking left to right and only looking rightward prevents double counting.
- Two queens are on a diagonal when `|Δcolumn| == |Δrow|` — not just when they look adjacent.
- A **negative** f(x) is clamped to **0** in this course's convention, and a zero-fitness chromosome gets **no bin** at all.
- Check whether column indices start at **0** or **1** — Lecture 4's exercises use 0, the 8Queen deck's board diagram uses 1. The fitness value is unaffected, but your written positions must match the convention stated in the question.
- 5 bits encode `0–31`, not `0–32`.
